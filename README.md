# VR 기반 로봇팔 모방학습 교육 프로젝트

## 1. 프로젝트 개요

### 1.1 프로젝트명

**Oculus Rift CV1 기반 Isaac Sim 로봇팔 원격조작 및 모방학습 프로젝트**

### 1.2 프로젝트 목적

본 프로젝트는 VR 장비인 **Oculus Rift CV1**을 학생의 조작 인터페이스로 활용하여, 가상 로봇팔을 직접 조작하고 그 움직임 데이터를 수집한 뒤, 수집된 시연 데이터를 이용하여 로봇팔의 작업 정책을 학습하는 것을 목표로 한다.

단순한 VR 체험에 그치지 않고 다음의 전체 개발 흐름을 경험하도록 구성한다.

> VR 조작 → 가상 로봇팔 제어 → 움직임 데이터 수집 → 데이터 전처리 → AI 모방학습 → 학습 결과 평가 → 실제 로봇 연계

### 1.3 핵심 구성 요소

| 구성 요소 | 역할 |
|---|---|
| Oculus Rift CV1 | 학생의 머리 움직임 및 컨트롤러 입력을 제공하는 VR 조작 인터페이스 |
| NVIDIA Isaac Sim | 가상 로봇팔, 작업 공간, 물체, 충돌 및 물리 환경을 시뮬레이션 |
| Python / ROS 2 | VR 입력, 로봇 제어 명령, 상태 데이터 및 시스템 간 통신 연결 |
| 데이터 로거 | 관절 상태, 말단 위치·자세, 그리퍼 상태, 시간 정보 및 시연 결과 저장 |
| NVIDIA Isaac Lab | 강화학습·모방학습을 위한 로봇 학습 환경 및 정책 학습 프레임워크 |

### 1.4 최종 프로젝트 예제

가장 적합한 기본 과제는 **Pick & Place**이다.

1. 테이블 위에 큐브 또는 간단한 작업물을 배치한다.
2. 학생이 Oculus Rift CV1 컨트롤러로 로봇팔을 조작한다.
3. 로봇팔의 그리퍼로 물체를 집는다.
4. 목표 위치로 이동한다.
5. 물체를 놓는다.
6. 성공적인 시연 데이터를 저장한다.
7. 여러 시연 데이터를 이용하여 AI 정책을 학습한다.
8. VR 조작 없이 학습된 정책이 동일한 작업을 수행하는지 평가한다.

> CV1의 실제 호환성은 운영체제, GPU 드라이버, Oculus 런타임, OpenXR 런타임 및 Isaac Sim 버전의 조합에 따라 달라질 수 있다. 본 개발에 앞서 반드시 별도의 호환성 POC를 수행한다.

# 5. 프로젝트 개발 상세

## 5.1 1단계: 로봇팔 시뮬레이션 환경 구축

### 목표

Isaac Sim에 로봇팔과 작업 공간을 구성하고, 기본적인 관절 제어 및 물리 동작을 확인한다.

### 개발 내용

1. 6축 로봇팔 모델 선택
2. 로봇팔 USD 또는 URDF 모델 불러오기
3. 바닥과 테이블 생성
4. 큐브, 원통 또는 작업물 생성
5. 그리퍼 모델 구성
6. 중력 및 충돌 설정
7. 관절 제한 설정
8. 카메라 및 조명 배치
9. 작업 성공 조건 정의

### 추천 초기 환경

- 6축 로봇팔 1대
- 테이블 1개
- 큐브 1~3개
- 목표 위치 1개
- 고정된 카메라 1대
- 그리퍼 1개

### 초기 검증 항목

- 로봇팔이 초기 자세로 이동하는가?
- 관절이 허용 범위를 벗어나지 않는가?
- 그리퍼가 정상적으로 열리고 닫히는가?
- 큐브와 로봇팔의 충돌이 감지되는가?
- 물체를 집었을 때 물리적으로 따라오는가?
- 목표 위치에 놓았을 때 성공 판정이 가능한가?

## 5.2 2단계: Oculus Rift CV1 입력 취득

### 목표

Oculus Rift CV1의 HMD 및 Touch 컨트롤러 입력을 프로그램에서 취득한다.

### 취득할 수 있는 입력

- HMD 위치
- HMD 회전
- 왼쪽 컨트롤러 위치·회전
- 오른쪽 컨트롤러 위치·회전
- 트리거 입력
- 그립 버튼 입력
- 조이스틱 입력
- 메뉴 버튼 및 기타 버튼
- 컨트롤러 추적 상태

### 입력 매핑 예시

| VR 입력 | 로봇팔 동작 |
|---|---|
| 오른쪽 컨트롤러 X 이동 | 말단 X 이동 |
| 오른쪽 컨트롤러 Y 이동 | 말단 Y 이동 |
| 오른쪽 컨트롤러 Z 이동 | 말단 Z 이동 |
| 컨트롤러 회전 | 말단 자세 변경 |
| 트리거 | 그리퍼 닫기 |
| 트리거 해제 | 그리퍼 열기 |
| 특정 버튼 | 데이터 기록 시작·종료 |
| 조이스틱 | 이동 스케일 또는 모드 조정 |

### 주의점

VR 컨트롤러의 실제 위치를 로봇팔의 말단 위치에 그대로 대입하면 작업 공간과 좌표계가 맞지 않을 수 있다. 따라서 다음 처리가 필요하다.

- 기준 자세 캘리브레이션
- VR 좌표계와 로봇 좌표계 변환
- 위치 스케일 조정
- 회전 표현 변환
- 로봇 작업 공간 제한
- 입력 필터링
- 안전한 최대 속도 제한

## 5.3 3단계: 좌표계 변환 및 말단 제어

### 기본 개념

VR 컨트롤러의 위치와 방향을 로봇팔의 목표 말단 위치와 방향으로 변환한다.

```text
VR Controller Pose
        │
        ▼
기준 좌표계 보정
        │
        ▼
위치 스케일 변환
        │
        ▼
로봇 작업 공간 제한
        │
        ▼
목표 말단 Pose
        │
        ▼
역기구학 또는 말단 제어기
        │
        ▼
관절 목표값
```

### 위치 변환 개념

VR 기준 위치를 `p_vr`, 로봇 기준 위치를 `p_robot`라고 하면 다음과 같은 형태로 매핑할 수 있다.

```text
p_robot = p_origin + S · R · (p_vr - p_vr_origin)
```

- `p_vr`: 현재 VR 컨트롤러 위치
- `p_vr_origin`: 캘리브레이션 시점의 VR 기준 위치
- `R`: VR 좌표계에서 로봇 좌표계로 변환하는 회전
- `S`: 위치 스케일
- `p_origin`: 로봇 작업 공간의 기준 위치

### 반드시 고려할 사항

- 로봇팔의 도달 범위
- 각 관절의 최소·최대 각도
- 특이점(Singularity)
- 자기 충돌
- 주변 물체와의 충돌
- 말단 속도와 가속도
- 그리퍼의 파지 가능 범위
- VR 입력의 노이즈와 지연

## 5.4 4단계: Python 및 ROS 2 연결

### 역할 분담

#### Python

- VR 입력 취득
- 입력 필터링
- 좌표계 변환
- 로봇 목표 자세 계산
- 데이터 기록
- 실험 자동화
- 결과 분석

#### ROS 2

- VR 입력 또는 목표 Pose 전달
- 로봇 상태 전달
- 관절 명령 전달
- 그리퍼 명령 전달
- 노드 간 통신
- 실제 로봇으로 확장할 때의 인터페이스 제공

### 예시 노드 구조

```text
vr_input_node
    └─ VR 컨트롤러 입력 취득

pose_mapping_node
    └─ 좌표 변환 및 목표 Pose 생성

robot_command_node
    └─ Isaac Sim 로봇팔 제어

state_logger_node
    └─ 관절 상태·말단 상태·행동 기록

evaluation_node
    └─ 작업 성공 여부 및 성능 계산
```

### 권장 Topic 예시

| Topic | 메시지 예시 | 내용 |
|---|---|---|
| `/vr/controller_pose` | PoseStamped | VR 컨트롤러 위치·자세 |
| `/robot/target_pose` | PoseStamped | 로봇 말단 목표 위치·자세 |
| `/robot/joint_states` | JointState | 관절 위치·속도·노력 |
| `/robot/gripper_command` | Float32 또는 커스텀 메시지 | 그리퍼 명령 |
| `/demo/start` | Bool | 시연 기록 시작 |
| `/demo/stop` | Bool | 시연 기록 종료 |
| `/demo/status` | String 또는 커스텀 메시지 | 시연 상태 |

> 실제 Isaac Sim과 ROS 2를 연결할 때는 사용 중인 Isaac Sim 버전의 ROS 2 브리지 및 지원 배포판을 확인해야 한다.

## 5.5 5단계: 데이터 로거 개발

### 목표

학생이 VR로 수행한 작업을 AI 학습에 사용할 수 있는 구조화된 시연 데이터로 저장한다.

### 기록 데이터

#### 로봇 상태

- 타임스탬프
- 6개 관절 위치
- 6개 관절 속도
- 관절 노력 또는 토크
- 말단 위치
- 말단 방향
- 그리퍼 상태
- 충돌 상태
- 작업 성공 여부

#### 사용자 입력

- VR 컨트롤러 위치
- VR 컨트롤러 방향
- 버튼 및 트리거 상태
- 입력 모드
- 시연 시작·종료 상태

#### 환경 상태

- 물체 위치
- 목표 위치
- 카메라 영상 경로
- 센서 데이터
- 에피소드 번호
- 시나리오 설정값

### 데이터 레코드 예시

```json
{
  "timestamp": 1.24,
  "episode": 3,
  "joint_position": [0.12, -0.35, 0.48, 0.10, 0.72, -0.15],
  "joint_velocity": [0.01, 0.02, -0.01, 0.03, 0.00, 0.01],
  "ee_position": [0.42, 0.18, 0.31],
  "ee_orientation": [0.0, 0.7, 0.0, 0.7],
  "gripper": 0.0,
  "action": [0.01, -0.02, 0.00, 0.00, 0.01, 0.00, 0.0],
  "object_position": [0.45, 0.20, 0.05],
  "goal_position": [0.70, 0.25, 0.05],
  "success": false
}
```

### 저장 형식 비교

| 형식 | 장점 | 용도 |
|---|---|---|
| CSV | 사람이 쉽게 확인 가능 | 교육용 기초 분석 |
| JSON | 구조화된 데이터 저장 | 이벤트·메타데이터 포함 |
| NPZ | NumPy 배열 저장에 편리 | Python 학습 파이프라인 |
| HDF5 | 대용량 시계열·영상 데이터에 적합 | 고급 데이터셋 |
| ROS 2 Bag | ROS 2 메시지 재생 가능 | 시스템 디버깅 및 재현 |

### 데이터 로깅 규칙

- 모든 데이터는 동일한 시간 기준을 사용한다.
- 관측값과 행동값의 타임스탬프를 일치시킨다.
- 시작·종료 이벤트를 명확히 기록한다.
- 실패한 시연도 별도 표시하여 분석에 활용한다.
- 데이터셋 버전을 관리한다.
- 시연자, 로봇 모델, 환경 설정 및 소프트웨어 버전을 메타데이터로 저장한다.

## 5.7 7단계: Isaac Lab 모방학습

### 목표

학생의 시연 데이터를 이용하여 VR 조작 없이 로봇팔이 작업을 수행하도록 정책을 학습한다.

### 관측값 예시

```text
observation =
[
  joint_position[6],
  joint_velocity[6],
  end_effector_position[3],
  end_effector_orientation[4],
  gripper_state[1],
  object_position[3],
  goal_position[3]
]
```

### 행동값 예시

```text
action =
[
  target_joint_position[6],
  gripper_command[1]
]
```

또는 말단 위치·자세 기반 제어를 사용할 수 있다.

```text
action =
[
  delta_x,
  delta_y,
  delta_z,
  delta_roll,
  delta_pitch,
  delta_yaw,
  gripper_command
]
```

### 학습 방식

#### 1. 행동 복제 기반 모방학습

시연 데이터의 관측값과 행동값을 입력으로 사용하여, 정책이 시연자의 행동을 예측하도록 학습한다.

- 입력: 로봇 상태 및 환경 상태
- 출력: 다음 행동 또는 목표 관절값
- 손실 함수: 행동 예측 오차
- 장점: 구조가 단순하고 교육에 적합
- 한계: 학습 데이터 분포 밖의 상황에 취약할 수 있음

#### 2. 강화학습

로봇이 목표를 달성하면 보상을 주고, 실패하거나 충돌하면 페널티를 주어 정책을 학습한다.

예시 보상 구성:

```text
보상 =
  목표물과 말단장치의 거리 감소 보상
+ 파지 성공 보상
+ 목표 위치 접근 보상
+ 작업 완료 보상
- 충돌 페널티
- 과도한 움직임 페널티
- 시간 지연 페널티
```

#### 3. 시연 데이터 + 강화학습

시연 데이터로 초기 정책을 만들고, 이후 강화학습으로 성능을 개선하는 방식이다.

## 5.8 8단계: 학습 결과 평가

### 평가 항목

| 평가 지표 | 의미 |
|---|---|
| 작업 성공률 | 목표 작업을 성공한 비율 |
| 평균 작업 시간 | 한 번의 작업에 소요되는 시간 |
| 위치 오차 | 목표 위치와 최종 위치의 차이 |
| 파지 성공률 | 물체를 정확히 잡은 비율 |
| 충돌 횟수 | 작업 중 충돌 발생 횟수 |
| 경로 길이 | 말단장치가 이동한 총 거리 |
| 관절 움직임 크기 | 관절별 움직임의 총량 |
| 재현성 | 동일한 조건에서 결과가 얼마나 일정한지 |
| VR 시연 대비 오차 | 학생 시연과 학습 정책의 차이 |

### 평가 실험 예시

1. 학습에 사용하지 않은 새로운 물체 위치를 준비한다.
2. VR 조작 없이 학습 정책을 실행한다.
3. 동일한 작업을 20~50회 반복한다.
4. 성공률과 평균 작업 시간을 측정한다.
5. 학습 전·후 성능을 비교한다.
6. 장애물 위치와 목표 위치를 바꾸어 일반화 성능을 평가한다.

### 성공 기준 예시

- 기본 환경에서 작업 성공률 80% 이상
- 충돌 없이 작업 완료
- 목표 위치 오차가 사전에 정한 허용 범위 이내
- 학습에 사용하지 않은 위치에서도 일정 수준의 성공률 확보
- 정책 실행 시간이 실시간 제어 주기에 적합

> 위 수치는 교육용 예시이며, 실제 로봇 모델과 작업 난이도에 맞춰 조정해야 한다.

# 9. 안전 및 운영상 주의사항

## 9.1 VR 안전

- VR 사용 전 주변 장애물을 제거한다.
- 장시간 사용 시 휴식 시간을 제공한다.
- 케이블 걸림을 방지한다.
- 어지럼증이나 불편함이 발생하면 즉시 중단한다.
- 외부 센서의 시야를 확보한다.

## 9.2 시뮬레이션 안전

- 로봇 관절 범위를 제한한다.
- 최대 속도와 가속도를 제한한다.
- 충돌 감지 및 비상 정지 기능을 구현한다.
- 초기에는 저속 모드로 동작시킨다.
- 학생이 임의로 안전 제한을 해제하지 못하도록 한다.

## 9.3 실제 로봇 적용 안전

- 시뮬레이션 결과를 실제 로봇에 바로 적용하지 않는다.
- 실제 로봇 적용 전 별도 안전 검증을 수행한다.
- 비상정지 장치를 준비한다.
- 작업 공간을 제한한다.
- 저속·저토크 조건부터 시험한다.
- 지도자 감독하에 단계적으로 시험한다.

# 11. 최종 정리

본 프로젝트는 다음의 기술 요소를 하나의 교육 프로젝트로 통합한다.

```text
Oculus Rift CV1
    ↓
VR 조작 인터페이스
    ↓
Python / ROS 2
    ↓
Isaac Sim 가상 로봇팔
    ↓
움직임 데이터 로깅
    ↓
데이터 전처리
    ↓
Isaac Lab 모방학습·강화학습
    ↓
학습 정책 평가
    ↓
실제 로봇 및 디지털 트윈 확장
```

핵심은 VR 장비 자체가 아니라, **학생의 조작 경험을 정량적인 로봇 데이터로 변환하고, 그 데이터를 AI 정책 학습으로 연결하는 전체 개발 파이프라인**을 교육하는 데 있다.

최종적으로 학생은 다음 질문에 답할 수 있어야 한다.

- VR 컨트롤러의 움직임을 로봇팔의 움직임으로 어떻게 변환하는가?
- 로봇팔의 상태와 행동을 어떤 형식으로 기록해야 하는가?
- 좋은 시연 데이터와 나쁜 시연 데이터는 무엇이 다른가?
- 모방학습 정책은 어떤 입력을 받아 어떤 출력을 생성하는가?
- 학습된 정책의 성능을 어떤 지표로 평가할 수 있는가?
- 시뮬레이션 결과를 실제 로봇에 적용할 때 어떤 문제가 발생하는가?
